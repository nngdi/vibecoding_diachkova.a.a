## 1. Описание интеграции

Во второй лабораторной работе Telegram-бот — учебный планировщик, созданный в Lab 1, был расширен подключением к базе данных SQLite.

В первой версии задачи и расписание сохранялись в JSON-файле. Во второй лабораторной хранение данных было перенесено в SQLite. Теперь бот не только сохраняет информацию, но и выполняет SQL-запросы для добавления, чтения, изменения, удаления и анализа данных.

Дополнительно были добавлены функции «Статистика» и «История», которые используют данные из базы.

## 2. Какой источник данных выбрали

В качестве источника данных была выбрана локальная база данных SQLite.

Файл базы:

```text
planner.db
```

База содержит две основные таблицы:

```text
tasks
lessons
```

## 3. Почему именно этот

SQLite была выбрана, потому что она встроена в Python и не требует отдельного сервера, регистрации или API-ключа.

Для учебного Telegram-бота этого достаточно, поскольку база позволяет:

- хранить задачи пользователей;
- хранить расписание;
- выполнять поиск и фильтрацию;
- изменять статус задач;
- удалять записи;
- получать историю;
- рассчитывать статистику.

По сравнению с JSON база данных лучше подходит для структурированной работы с большим количеством записей.

## 9. Реализация

Интеграция реализована с помощью встроенной библиотеки Python `sqlite3`.

При запуске программы вызывается функция:

```python
init_db()
```

Она создаёт таблицы `tasks` и `lessons`, если они ещё не существуют.

После этого все операции с задачами и расписанием выполняются через SQL-запросы.

## 10. Как работает интеграция

Когда пользователь создаёт задачу, бот получает название, дату, время и приоритет, после чего выполняет SQL-запрос `INSERT`.

При просмотре задач используется `SELECT`.

При нажатии «Выполнено» выполняется `UPDATE`.

При удалении задачи или занятия выполняется `DELETE`.

Таким образом, в проекте реализованы основные CRUD-операции:

- Create;
- Read;
- Update;
- Delete.

Кнопки «Статистика» и «История» также получают информацию непосредственно из SQLite.

## 11. Ключевые фрагменты кода

### Подключение к базе

```python
def connect():
    conn = sqlite3.connect(DB_FILE)
    conn.row_factory = sqlite3.Row
    return conn
```

### Добавление задачи

```python
conn.execute(
    '''
    INSERT INTO tasks
    (user_id, text, due_datetime, priority, done, created_at)
    VALUES (?, ?, ?, ?, 0, ?)
    ''',
    (user_id, text, due_datetime, priority, created_at)
)
```

### Получение активных задач

```python
SELECT *
FROM tasks
WHERE user_id = ?
AND done = 0
ORDER BY due_datetime, priority
```

### Отметка задачи выполненной

```python
UPDATE tasks
SET done = 1,
    completed_at = ?
WHERE user_id = ?
AND id = ?
```

### Получение истории

```python
SELECT *
FROM tasks
WHERE user_id = ?
AND done = 1
ORDER BY completed_at DESC
LIMIT 10
```

### Получение статистики

Для статистики используются запросы `COUNT(*)`, например:

```python
SELECT COUNT(*)
FROM tasks
WHERE user_id = ?
AND done = 0
```

## 17. Трудности и решения

Главной задачей второй лабораторной было перейти от простого хранения данных в JSON к работе с базой данных и при этом не потерять функциональность первой версии Telegram-бота.

## 18. С какими проблемами столкнулись

Во время разработки возникли следующие сложности:

- потребовалось изменить структуру хранения данных;
- необходимо было переписать операции добавления, получения и удаления задач;
- потребовалось хранить статус выполненных задач;
- для истории понадобилось сохранять время выполнения;
- необходимо было получать статистику сразу по нескольким категориям;
- требовалось обрабатывать ошибки базы данных;
- при работе в Google Colab база существует только в текущей среде, если её отдельно не сохранить.

## 19. Как их решили

Вместо работы с JSON были созданы две таблицы SQLite — `tasks` и `lessons`.

Для взаимодействия с данными были созданы отдельные функции:

```text
add_task()
active_tasks()
complete_task()
delete_task()
add_lesson()
lessons()
delete_lesson()
history()
stats()
```

Для безопасной передачи пользовательских данных в SQL используются параметризованные запросы с символом `?`.

Для возможных ошибок базы добавлена обработка `sqlite3.Error`.

Для истории выполненных задач добавлено поле `completed_at`.

Для статистики используются SQL-запросы `COUNT(*)`.
